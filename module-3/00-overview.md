# Перед началом модуля 3

![Топология](../assets/page-125-img-01.jpeg)

Нужны работающие сеть HQ↔BR, DNS/время, Samba DC на BR-SRV, доменный HQ-CLI, Ansible на BR-SRV, Apache/MariaDB (`webdb`) на HQ-SRV, Docker на BR-SRV и nginx-прокси на ISP. Проверь фактические настройки стенда; не разворачивай домен и приложения повторно.

| Узел | IPv4 примера |
| --- | --- |
| HQ-SRV | 192.168.100.2 |
| BR-SRV / DC | 192.168.0.2 |
| HQ-CLI | 192.168.200.2; сеть 192.168.200.0/24 |
| HQ-RTR WAN / LAN / туннель | 172.16.1.2 / 192.168.100.1 / 10.10.10.1 |
| BR-RTR WAN / туннель | 172.16.2.2 / 10.10.10.2 |
| ISP → HQ / BR | 172.16.1.1 / 172.16.2.1 |

Сверь IP, имена портов, SSH-порты и пароли. Для Linux-серверов в примере SSH — 2026. Нужны `Additional.iso` (CSV, playbook), дистрибутив КриптоПро CSP и установщик Кибер Бэкап.

Проверки: доменный вход на HQ-CLI; `web.au-team.irpo` и `docker.au-team.irpo` через ISP; ping между серверами; `ansible all -m ping` из `/etc/ansible` на BR-SRV.

**Отчет:** выбор и параметры IPsec, изменения OSPF; выбор ПО мониторинга, метрики и порты. Итоговый файл — `ФамилияУчастникаМодуль3`.

> **Исправления примеров:** импорт выполняется на BR-SRV; адреса IPsec на BR зеркальны HQ; логи используют согласованный UDP 514; обе резервные копии сохраняются на HQ-CLI. HTTPS должен сохранять аутентификацию WEB из модуля 2.
