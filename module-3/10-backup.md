# Кибер Бэкап — HQ-SRV; хранилище — HQ-CLI

Нужны два плана: `/etc` со всеми подкаталогами и MySQL/MariaDB `webdb`. **Оба** сохраняются на HQ-CLI в `/backup`.

## 1. Подготовка и установка

На обоих узлах:

```bash
uname -r
apt-get update
apt-get install -y gcc make
lsblk
mkdir -p /mnt/cyberbackup
```

Установи исходники/заголовки **работающего** ядра согласно требованиям установщика. В исходнике пакеты для 6.12; не копируй их при другом ядре. Если потребовалось обновление ядра, сначала перезагрузись и повторно проверь `uname -r`.

Смонтируй именно ISO установщика, например на HQ-SRV:

```bash
mount /dev/sr1 /mnt/cyberbackup
ls /mnt/cyberbackup
bash /mnt/cyberbackup/CyberBackup_18_64-bit.x86_64
```

На HQ-CLI повтори с его CD-устройством (в исходнике `/dev/sr0`). Имя установщика сверь по `ls`.

| Узел | Компоненты |
| --- | --- |
| HQ-SRV | Management Server, Agent for Linux, Agent for MySQL/MariaDB |
| HQ-CLI | Agent for Linux, Storage Node; подключение к Management Server HQ-SRV |

> **Важно:** в задании рекомендована версия 17.4 или аналог, в примере — 18. Используй предоставленную версию и проверь совместимость с ОС/ядром; названия пунктов GUI могут различаться. [Документация Кибер Бэкап](https://cyberprotect.ru/documentation/backup).

## 2. Организация, администратор, хранилище

На HQ-SRV создай локальную учетную запись, если ее еще нет:

```bash
useradd -m irpoadmin
passwd irpoadmin
```

Пароль — `P@ssw0rd`. В веб-консоли `http://hq-srv.au-team.irpo:9877` войди учетной записью администратора сервера (пароль root бери со стенда). В «Настройки → Учетные записи» создай организацию/подразделение **irpo**, добавь **irpoadmin** с ролью администратора; проверь его вход.

На HQ-CLI:

```bash
mkdir -p /backup
```

В консоли зарегистрируй Storage Node HQ-CLI и создай управляемое хранилище, выбрав **его локальный путь `/backup`**. Дай службе узла хранения доступ к каталогу. Проверь, что HQ-SRV и HQ-CLI зарегистрированы и доступны.

## 3. Два плана и запуск

| План для HQ-SRV | Источник | Назначение |
| --- | --- | --- |
| ETC | Файлы/папки: `/etc`, включая подкаталоги | хранилище HQ-CLI, `/backup` |
| WEBDB | Базы MySQL/MariaDB: `webdb` | то же хранилище HQ-CLI |

Для WEBDB задай учетную запись БД с правами, требуемыми агентом, проверь обнаружение webdb. Обычный пользователь приложения может не иметь достаточных прав для резервного копирования.

Настрой доступную в выбранной версии защиту от шифровальщиков (Active Protection/защита резервных копий); проверь, что компонент включен и поддерживает используемую ОС. Если такой компонент недоступен, установка одного агента не выполняет это требование — нужен совместимый вариант решения.

Запусти каждый план вручную. Ожидается статус «Успешно», две точки восстановления, данные в хранилище HQ-CLI. Восстанови тестовый файл из `/etc` в отдельный каталог; БД — в отдельную тестовую базу/среду, не поверх рабочей webdb.

> **Важно:** `/backup_db` на HQ-SRV из старого примера не выполняет требование хранения БД на HQ-CLI. Проверяй выбранный узел назначения, результат заданий и возможность восстановления; не ограничивайся созданием планов.
