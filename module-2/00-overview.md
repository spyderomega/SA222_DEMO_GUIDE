# Перед началом модуля 2

![Топология](../assets/page-078-img-01.jpeg)

В отдельном стенде уже настроены IPv4/шлюзы, NAT, туннель, маршрутизация, SSH, DHCP и DNS; созданы `sshuser` на серверах и `net_admin` на маршрутизаторах. У HQ-SRV — два дополнительных диска по 1 ГБ.

Адреса примера; перед работой сверь с фактическим стендом:

| Узел | IPv4 / доступ |
| --- | --- |
| ISP → HQ / BR | 172.16.1.1 / 172.16.2.1 |
| HQ-RTR → ISP | 172.16.1.2 |
| BR-RTR → ISP | 172.16.2.2 |
| HQ-SRV | 192.168.100.2, SSH 2026 |
| BR-SRV | 192.168.0.2, SSH 2026; будущий DC |
| HQ-CLI | пример 192.168.200.2, сеть 192.168.200.0/24 |
| HQ-RTR, туннель | 10.10.10.1 |
| BR-RTR, LAN | 192.168.0.1 |

Минимальная проверка на Linux:

```bash
hostnamectl
ip -c a
ip -c r
cat /etc/resolv.conf
timedatectl
```

Проверь ping до шлюза и между HQ/BR, Интернет и разрешение имен. Имя BR-SRV должно быть `br-srv.au-team.irpo`.

> **DNS:** после развертывания Samba HQ-CLI использует DNS BR-SRV (`192.168.0.2`), а не только прежний DNS HQ-SRV. Перед вводом в домен проверь записи AD и время.

Для веба нужен подключенный `Additional.iso`: на BR-SRV каталог `docker`, на HQ-SRV — `web`. Монтирование выполняется отдельно на каждом сервере; `/dev/sr0` сверь через `lsblk`.

> **Источник данных:** в практикуме есть противоречия между заданием и примерами. Ниже для Docker используются `webapp / P@ss2026-db / appdb_maria`, для Apache — `web / P@ssw0rd / webdb`, для RAID — раздел на md0. Названия образов и переменных Docker уточни в `docker/readme.txt` своего ISO.
